# حسابداری صدرا — مرورگر، نسخهٔ آزمایشی ۲۰۴

نشانی سایت: https://thumper9480-droid.github.io/hesabdari/

پس از انتشار، صفحه را با `Ctrl+F5` تازه‌سازی کنید. پیش از شروع، از منوی پشتیبان‌گیری یک فایل پشتیبان دانلود کنید و تب‌های قدیمی برنامه را ببندید. اطلاعات بین دستگاه‌ها همگام نمی‌شود؛ داده‌ها در مرورگر همان دستگاه قرار دارند.

## روش استفاده

۱. در «معرفی واحدها» و «معرفی دارایی‌ها»، واحد و دارایی پایه را بررسی کنید.
۲. محل‌ها، انواع صندوق، گروه‌های افراد، دسته‌های هزینه، منابع و انواع درآمد را تعریف کنید.
۳. کالا را با مبنای تعداد، وزن یا ارز، واحد نرخ، عیار و قواعد کارمزد معرفی کنید. وزن استاندارد و وزن واقعی دو فیلد مستقل‌اند. برای کارمزد تومانی، واحد ارز تومانی با کد داخلی `IRT` ملاک است؛ نام دارایی تعیین‌کنندهٔ محاسبه نیست.
۴. از «ثبت سند»، خرید یا فروش را ثبت کنید. این کار به‌تنهایی موجودی فیزیکی ایجاد نمی‌کند.
۵. برای ورود یا خروج واقعی، «تحویل واقعی کالا» و معاملهٔ مرتبط را انتخاب کنید. تحویل جزئی مجاز است.
۶. برای پرداخت یا دریافت وجه همان معامله، «تسویه مالی / کارمزد» را انتخاب کنید.
۷. برای حواله یا انتقال، نوع و حساب مبدأ و مقصد و توافق را مشخص کنید. انتقال داخلی، دارایی کل را تغییر نمی‌دهد.
۸. در «موجودی»، «حساب اشخاص» و «گزارش»، گردش‌ها و مانده‌های تفکیک‌شده را بررسی کنید. مقدار مثبت حساب شخص یعنی طلب ما و مقدار منفی یعنی بدهی ما.
۹. PDF از دکمهٔ «چاپ / ذخیره PDF» و سپس گزینهٔ Save as PDF مرورگر تهیه می‌شود.

اگر مانده‌ای از نسخهٔ قبل دارید، ابتدا پیام بررسی انتقال را مطالعه کنید و مانده‌ها را با پشتیبان و اصل اسناد تطبیق دهید. طلای قدیمی با مبنای معادل ۷۵۰ مشخص می‌شود؛ آن را با وزن واقعی محمولهٔ جدید یکی نگیرید.

## اجرای محلی و آزمون

از همان checkout موجود استفاده کنید. هر وظیفهٔ ابری از قبل محیط مستقل دارد؛ مگر با درخواست صریح کاربر worktree نسازید.

```bash
cd /workspace/hesabdari
python3 -m http.server 8001 --bind 127.0.0.1
```

ساخت یا نصب وابستگی برای برنامه لازم نیست. فایل‌های `index.html`، `next-core.js`، `next-ui.js`، `next-ui.css` و پوشهٔ `fonts` باید کنار هم باشند. بستهٔ ZIP جدید همین فایل‌ها را دارد.

```bash
node --test tests/ledger.test.cjs
node tests/browser.cjs
node tests/compatibility.cjs
node tests/reports.cjs
node tests/banks.cjs
```

آزمون‌های مرورگر به Chromium و Playwright محیط نیاز دارند. مسیرهای پیش‌فرض در ابزار آزمون با متغیرهای غیرمحرمانهٔ `CHROMIUM_PATH` و `PLAYWRIGHT_MODULE` قابل تنظیم‌اند؛ `APP_URL` برای آزمون اصلی قابل تنظیم است. پیش‌فرض آزمون‌های سازگاری و گزارش پورت ۸۰۰۱ است.

## فایل‌ها و مرز مسئولیت

- `next-core.js`: محاسبات دقیق، اعتبارسنجی و دفتر رویداد.
- `next-ui.js` و `next-ui.css`: صفحات جدید، گزارش و خروجی.
- `index.html`: پوسته و سازگاری با اسناد و ابزارهای قبلی.
- `docs/REQUEST_STATUS.md`: وضعیت پرامپت‌ها، تصمیم‌ها و محدودیت‌ها.
- `docs/requests`: متن اصلی درخواست‌های پیوست.

بانک‌ها، حساب‌های هر بانک، شماره حساب و واحد پول مستقل در بخش بانک‌ها مدیریت می‌شوند. موارد دارای سند حذف نمی‌شوند؛ ویرایش و غیرفعال‌سازی مجاز است. کنترل‌های سمت سرور و چندکاربره به زیرساخت دیگری نیاز دارند و در این نسخه ارائه نشده‌اند.
